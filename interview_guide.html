Technical Interview Master Guide

Apex Banking Platform

Fullstack & Backend System Architecture, OOP Patterns, Security & MongoDB Flow

Stack: Python Flask + PyMongo + MongoDB + React Vite
Authentication: JWT (HS256) + Salted Bcrypt
Author Role: Fullstack / Frontend Engineer

1 High-Level Architecture & Request Flow

The application follows a clean Tiered REST Architecture. Here is how a request travels from the user interface down to database storage:

Example: Fund Transfer Execution (Sarah transfers ₹1,000 to David)
  1. Frontend Trigger: User clicks "Transfer" in TransferMoney.jsx. The centralized API client api.js issues an HTTP POST with header Authorization: Bearer <JWT_TOKEN>.
  2. Routing & Application Factory: Flask receives the request on port 5000 and routes it to the transactions_bp blueprint defined in transactions.py.
  3. Security Middleware Interception: The @token_required decorator extracts the Bearer token, validates the HS256 cryptographic signature, verifies that the 5-minute session has not expired, and confirms the account is not frozen. It attaches request.current_user to the execution context.
  4. Role-Based Access Guard: The @role_required(["customer", "manager"]) decorator validates permissions.
  5. Business Logic & Validation: Checks source account balance, enforces the ₹100 minimum balance for Savings accounts, applies the ₹1.50 fee for Business accounts, and verifies the destination account.
  6. Atomic Database Persistence: Performs atomic updates in MongoDB (db.accounts), creates two ledger records (transfer_out and transfer_in) in db.transactions, and records an immutable audit log in db.audit_logs.
  7. Response: Returns HTTP 200 OK with the new balance and unique transaction reference ID. The React frontend updates its local state and renders an official digital receipt.

3 Software Engineering & OOP Concepts Used

1. Singleton Pattern (Connection Pool in database.py)

Problem: Creating a new database connection on every request causes connection leaks, high memory usage, and socket exhaustion.

Solution: The Database class stores static references (_client and _db). All parts of the backend reuse this single, thread-safe connection pool.

2. Application Factory Pattern (create_app() in __init__.py)

Concept: The Flask application is instantiated dynamically inside a factory function rather than globally.

Benefit: Enables seamless configuration switching between development, testing (with mocked database), and production environments.

3. Decorator Pattern / Aspect-Oriented Programming (in middleware.py)

Concept: Custom Python decorators (@token_required, @role_required) wrap route functions.

Benefit: Cross-cutting concerns like token verification, session timeout checks, and role enforcement are decoupled from business logic, adhering to the Don't Repeat Yourself (DRY) principle.

4. Encapsulation & Configuration Management (in config.py)

Concept: Secrets, interest percentages, minimum balance thresholds, and database connection strings are encapsulated in the Config class and read from environment variables (.env).

5 Core Banking Rules & Business Logic

Feature Area Rules & Validation Applied
Savings Account 6.0% APY annual interest. Requires ₹100.00 minimum initial deposit & balance. Withdrawals dropping balance below ₹100 are rejected. Zero transaction fees.
Business Account 9.0% APY annual interest. No minimum balance required. Flat ₹1.50 fee charged on every withdrawal and outgoing fund transfer.
Account Statuses Active (Full permissions), Frozen (All debits and credits blocked), Closed (Deactivated). Only Managers have permission to alter account status.
Session Timeout Customer Role: Strict 5-minute lifetime encoded in JWT. Topbar countdown alerts at ≤20s. Manager Role: 24-hour administrative lifetime.
Audit Compliance Every critical state change (login, transfer, account status update) writes an immutable record with IP address and JSON payload.

6 Client Interview Cheat Sheet (Top Q&As)

Q1: "Can you walk me through the backend architecture of this project?"
"The backend is built with Python Flask using a modular Blueprint architecture connected to MongoDB via PyMongo. We implemented the Application Factory pattern for flexible configuration, a Singleton connection pool for MongoDB, and custom middleware decorators for JWT authentication and Role-Based Access Control (RBAC). It powers multi-tier bank accounts, atomic fund transfers with fee calculations, a 5-minute customer session timeout, and an immutable compliance audit trail."
Q2: "How is authentication, password security, and session management implemented?"
"Passwords are encrypted using Bcrypt with 12 salt rounds before database insertion. Upon login, we issue signed JSON Web Tokens (HS256) containing the user's role and expiration. Customers have a strict 5-minute session lifetime, while managers receive 24-hour access. On every API request, our @token_required decorator extracts the Bearer token, validates the signature, checks for expiration, and verifies the user is not suspended."
Q3: "How is MongoDB structured and how do you ensure data integrity?"
"We use 4 primary collections: users, accounts, transactions, and audit_logs. We enforce unique indexes on emails, account numbers, and transaction IDs to guarantee data consistency. For fund transfers, we perform atomic updates using MongoDB's operator to ensure balances remain strictly synchronized, followed by creating double-entry ledger records and audit entries."
Q4: "What specific banking rules did you implement?"
"We implemented two specialized account types: Savings Accounts (6.0% APY, ₹100 minimum balance rule) and Business Accounts (9.0% APY, ₹1.50 per-transaction fee). We also built manager controls allowing administrators to update account statuses between Active, Frozen, and Closed, along with an automatic annual interest calculation engine."
Q5: "How does the React frontend interact with the Flask backend?"
"The frontend uses a centralized API service that automatically attaches the JWT Bearer token to all outgoing requests. If a customer session expires (401 response), the frontend catches it globally, displays a slide-over expiration warning, and safely redirects the user to login."
